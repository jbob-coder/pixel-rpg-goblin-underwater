## Authority barrier

This directory preserves historical implementation, migration, verification, device, and continuation records.

Files here do **not** become current Pixel RPG design, camera, visual, sprite, gameplay, branch, workflow, or runtime authority merely because they exist or were once build-verified.

Current work begins from:

1. current creator instruction;
2. live production `main`;
3. `START_HERE_NEW_CHAT.md`;
4. current repository map/master reference;
5. exact current source/tests;
6. exact same-SHA build/device evidence;
7. current issue register.

Historical handoffs are consulted only for bounded provenance, compatibility, regression history, or exact old evidence.

## Preservation rule

Do not rewrite old handoffs to pretend they implemented a newer design.

Old third-person, aerial, legacy-coordinate, old-branch, or old-workflow statements remain factual history for those checkpoints.

When current source still depends on a subsystem documented here, the handoff is technical provenance—not current design authority.

## Verification law

Keep these evidence layers separate:

`source/readback ≠ static gate ≠ Godot parse ≠ headless/runtime gate ≠ APK build ≠ phone install ≠ phone runtime ≠ visual acceptance ≠ sustained performance`

A historical PASS proves only the exact revision/device/build it names.
